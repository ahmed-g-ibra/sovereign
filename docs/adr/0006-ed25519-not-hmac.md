# 6. Ed25519 request signing, not HMAC

Date: 2026-10-21

## Status

Accepted

## Context

Probes must authenticate every upload. The obvious choice is a shared secret
and HMAC-SHA256: simple, fast, available in both standard libraries, and what
most APIs of this shape use.

It has one property worth thinking about. HMAC is symmetric, so the server has
to store a secret that can produce valid signatures for a probe. A database
dump therefore contains everything needed to impersonate the entire fleet and
write fabricated measurements into a public dataset.

## Decision

Ed25519. The agent generates a keypair during enrolment and sends only the
public half. The server stores public keys and nothing else.

## Consequences

- An attacker with full read access to the database can read every measurement
  and forge none. For a project whose only real asset is the credibility of its
  numbers, that is the property worth paying for.
- A probe's private key never crosses the network, not even once at enrolment.
- Revocation is deleting a public key.
- Key rotation needs a signed rotation endpoint, which does not exist yet.
- Verification costs more CPU than HMAC. At the projected six writes per second
  this is not measurable.
- Python needs `cryptography`; Go has Ed25519 in the standard library, so the
  agent stays dependency-free.
- The canonical string is now duplicated in two languages. A known-answer
  fixture is asserted on both sides (`sign_test.go` and `test_signing.py`) so
  that drift fails a test rather than silently rejecting every upload.
